# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Running the app

```bash
pip install flask requests werkzeug
python3 app.py
```

Opens at http://localhost:5001. The database (`instance/pool.db`) and default accounts are created automatically on first run.

To seed a pool with completed fixtures and scored picks for testing:

```bash
python3 seed_test_scoring.py
```

To use live match data instead of mock fixtures:

```bash
export FOOTBALL_DATA_API_KEY=your_key_here
python3 app.py
```

## Architecture

Three Python modules and a `templates/` folder — no framework beyond Flask.

**`app.py`** — all routes. Auth is handled by two decorators (`@login_required`, `@admin_required`) applied directly to route functions. `current_user()` is injected into every template via `@app.context_processor`. Picks are submitted via JSON AJAX (`/pool/<id>/pick`); all other forms use standard POST/redirect.

**`database.py`** — every function opens a fresh `sqlite3` connection, runs its query, commits if needed, and closes. No connection pooling; no ORM. All primary keys are UUIDs (generated by the caller with `str(uuid.uuid4())`). Schema is in `init_db()` — safe to call repeatedly (all `CREATE TABLE IF NOT EXISTS`). The scoring job is `calculate_scores_for_fixture()`: it's idempotent because `score_log` has a `UNIQUE(pick_id)` constraint.

**`fixtures.py`** — wraps the football-data.org API with a 15-minute in-memory cache (`_cache` dict). If no API key is set, `_load_mock_fixtures()` loads 24 hardcoded group-stage matches. Flag SVGs come from flagcdn.com using the `FLAG_CODES` dict; unknown teams fall back to `"un"` (UN flag).

## Key data model relationships

```
users ──< pool_members >── pools
fixtures ──< picks ── users, pools
picks ──< score_log
scoring_config (append-only; latest row by updated_at wins)
```

Picks are locked once a fixture's `kick_off` timestamp is in the past — enforced in both the AJAX endpoint and the template (buttons are disabled client-side).

## Scoring

Admin enters a result on `/admin` → `update_fixture_result()` writes `home_score`, `away_score`, and a derived `result` code (`H`/`A`/`D`) → `calculate_scores_for_fixture()` awards `points_win` or `points_loss` from the active `scoring_config` row. Draw predictions only score if the actual result was also a draw.
